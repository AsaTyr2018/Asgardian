# Security Policy

## Supported versions

Security fixes are handled on the current main development line unless a
maintainer announces additional supported release branches.

## Reporting a vulnerability

Do not open a public issue for vulnerabilities.

Report security concerns privately to the project owner or maintainer. If no
private contact is published yet, request a private disclosure channel through
the repository owner.

Please include:

- affected version or commit
- clear reproduction steps
- impact and affected component
- any relevant logs or screenshots with secrets removed

## Secrets and infrastructure data

Never include credentials, API keys, private keys, tokens, certificates, local
hostnames, private IP addresses, generated artifacts, or diagnostic dumps in a
public report.
